## 2. 介面與資料格式

| 項目 | F1 行為 |
| --- | --- |
| 功能選擇 | `fn_sel == 3'd1`，同次模擬中維持不變。 |
| 時脈與 reset | 正緣觸發，`rst` 為非同步高有效。 |
| 輸入 | 每次 8 bits，16 bytes 組成一個 128-bit block。 |
| 輸入順序 | 低位元組先送；第一個 byte 寫入 `data_buf[7:0]`，最後一個寫入 `[127:120]`。 |
| 區塊格式 | 高 64 bits 為原始 key，低 64 bits 為 plaintext。 |
| 輸出格式 | `iot_out = {main_key, des_result}`，保留原始 key。 |
| 輸出有效 | 每筆結果讓 `valid` 拉高一個 cycle；無效時不需清除 `iot_out`。 |

接收時使用 `data_buf[(byte_count * 8) +: 8]` 定址，`byte_count` 為 4 bits，索引為 0 至 15。RTL 不依賴總測資筆數，也不硬編碼 golden 答案。

## 3. 控制流程與握手

| 狀態 | 動作 |
| --- | --- |
| `WAIT_DATA` | 當 `in_en` 且選擇 F1 時，收取一個 byte 並更新索引。 |
| `LOAD_INPUT` | 從完整的 `data_buf` 擷取 `main_key` 與 `des_block`。 |
| `INIT` | 載入 IP 後的 L0/R0、PC1 後的 C0/D0，並將輪數設為 1。 |
| `ROUND` | 每 cycle 完成一輪，共 16 輪，同時更新資料與金鑰暫存器。 |
| `OUTPUT` | 擷取密文、拉高 `valid`、降低 `busy`，回到 `WAIT_DATA`。 |

### busy 的時序

原始 TB 在上升緣檢查 `busy`，經過 `DEL` 後才驅動下一個 byte，DUT 在再下一個上升緣接收。因此暫停輸入存在一個 byte 的在途延遲，並非通用的同拍 ready/valid 協定。

- 接收第 15 個 byte，即更新前 `byte_count == 14` 時，拉高 `busy`。
- TB 在該上升緣仍看到舊的 `busy=0`，因此會送出第 16 個 byte。
- 下一個上升緣，即 `byte_count == 15` 時，DUT 仍依 `in_en` 接收最後一個 byte；不能額外用 `!busy` 擋掉它。
- 計算期間維持 `busy=1`，輸出結果時再降為 0。

### 非阻塞賦值與輸出時序

時脈區塊使用 `<=`，同一上升緣的右側運算使用更新前的暫存器值。因此保留以下狀態分隔：

- `LOAD_INPUT` 與 `INIT` 分開，避免對舊的 key 或 plaintext 做初始化。
- 最後一輪先存入 L16/R16，再由下一個上升緣的 `OUTPUT` 擷取結果，避免輸出來自 L15/R15 的資料。
- L16/R16 更新後，FP 組合邏輯可在兩個上升緣之間算出結果，不需等到 `OUTPUT` 的上升緣才開始計算。
- 非 reset 路徑預設 `valid <= 0`，只在 `OUTPUT` 覆寫為 1，形成單 cycle 脈波。

## 4. DES 資料路徑

使用迭代式架構，共用一套 round datapath，每 cycle 處理一輪，而非展開 16 套硬體。

```text
64-bit plaintext
    -> IP
    -> L0 / R0
    -> 16 rounds
    -> {R16, L16}
    -> FP
    -> 64-bit ciphertext
```

每輪依 Feistel 規則更新：

```verilog
left_reg  <= right_reg;
right_reg <= left_reg ^ f_result;
```

F 函數的位寬依序為：

```text
right_reg (32)
    -> Expansion (48)
    -> XOR round_key (48)
    -> 8 parallel S-boxes (8 x 6-bit input, 8 x 4-bit output)
    -> sbox_result (32)
    -> P permutation (32)
    -> f_result (32)
```

IP、Expansion、P、FP、PC1、PC2 均依作業 Excel 提供的 bit index 實作為固定接線。函式與連續指定表示組合邏輯，不會自行增加 clock cycle。

### S-box

八個 S-box 各自使用不同的 64 項 `case` 表，輸入 6 bits、輸出 4 bits，並行運作。

```verilog
address = {box_in[5], box_in[0], box_in[4:1]};
```

外側兩個 bits 組成 row，中間四個 bits 組成 column。`address` 是查表地址，不是輸出值；RTL 中以 `6'd0` 至 `6'd63` 表示重排後地址，等同 `row * 16 + column`。

| S-box | `mixed_right` 輸入範圍 | `sbox_result` 輸出範圍 |
| --- | --- | --- |
| S1 | `[47:42]` | `[31:28]` |
| S2 | `[41:36]` | `[27:24]` |
| S3 | `[35:30]` | `[23:20]` |
| S4 | `[29:24]` | `[19:16]` |
| S5 | `[23:18]` | `[15:12]` |
| S6 | `[17:12]` | `[11:8]` |
| S7 | `[11:6]` | `[7:4]` |
| S8 | `[5:0]` | `[3:0]` |

例如 S2 收到 `6'b100101`，row 為 `11`、column 為 `0010`，重排地址為 `6'b110010`，查表結果為十進位 10，即 `4'b1010`。

### 金鑰排程

- 保留原始 64-bit `main_key`，用於最後輸出。
- PC1 將 key 轉為 56 bits，拆成 28-bit C0 與 28-bit D0。
- 第 1、2、9、16 輪各循環左移 1 bit，其餘輪各循環左移 2 bits。
- 每輪由目前 C/D 旋轉得到下一組 C/D，再經 PC2 產生 48-bit `round_key`。
- 第 1 輪由 C1/D1 產生 K1，第 16 輪由 C16/D16 產生 K16。
- 左右半部各自旋轉，不混用來源；不儲存全部 16 組 subkey。

## 5. 測試方式與結果

從 workspace 根目錄執行：

```sh
cd 1151_hw4/01_RTL
iverilog -g2005 -Wall -Dp1 -Dvcd -s test \
  -o /tmp/IOTDF_F1.vvp ../00_TESTBED/testfixture.v IOTDF.v
vvp -n /tmp/IOTDF_F1.vvp -none
```

`-Dp1` 選擇公開 pattern1；未定義 F2/F3/F4 時，原始 TB 預設測試 F1。`-Dvcd` 避免使用 Icarus 不支援的 FSDB 系統工作；`-none` 停用波形輸出，避開本次執行環境無法寫入 VCD 的限制。

| 項目 | 結果 |
| --- | --- |
| 編譯 | Icarus Verilog，Verilog-2005 模式，`-Wall` 編譯通過。 |
| 測資 | pattern1 F1，共 64 筆。 |
| 比對 | P00 至 P63 全部正確，64 passed、0 errors。 |
| 時脈週期 | 使用原始 TB 的 6.5 ns。 |
| TB 回報總模擬時間 | 14,995.50 ns，包含 TB 的收送流程，不是單筆 DES 延遲。 |
| TB 結論 | `Congratulation! All results are correct`。 |

未修改官方 TB、輸入資料與 golden。此結果是 RTL 功能模擬證據，不代表實體電路已滿足 6.5 ns timing，也不是 PPA 量測結果。
